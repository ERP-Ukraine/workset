# workset_dispatch — «Виїзди»

Модуль Odoo 19.0 для репозитория Odoo.sh `ERP-Ukraine/workset`. Здесь только устройство (модели, поля, экраны, повторы, карточка); данные
и чтение Pipedrive делает инструмент штаба `tools/odoo_dispatch.js`. **Модуль не ходит в сеть и не хранит ключей.**

## Что делает
- **Виїзд** — стандартная заявка подбора `hr.applicant` с полями `workset_*`. В день «Даты отправки» сделки Pipedrive инструмент передаёт
  модулю простые словари — метод `hr.applicant.workset_dispatch_import(items, dry_run=False)`; модуль заводит заявку в этапе «Виїзд».
- **Повторы** при создании заявки среди всех карточек всех фирм (с архивом). Сильное совпадение — тот же контакт Pipedrive
  (`hr.employee.workset_pd_person_id`), либо ОСНОВНОЙ телефон контакта (последние 9 цифр; телефон, записанный у двух разных имён, общий
  и не считается) вместе с хотя бы слабо совпавшим именем. Слабое («проверить дубль», не слияние): только имя; основной телефон, но имя
  другое; добавочный телефон контакта при любом имени. Имя: кириллические двойники латиницы сложены, пробелы схлопнуты, каждое слово
  совпадает со словом карточки с расстоянием правки до 2 (до 1 у четырёхбуквенных, точно у коротких) и общей первой буквой, либо по
  паспортным вариантам UA/BY/RU (-AU ≈ -OV, SIARHEI ≈ SERGEI ≈ SERHII), либо по таблице равнозначных ИМЁН с разной первой буквой
  (`NAME_GROUPS` в `models/names.py`: OLEKSANDR ≈ ALEKSANDR ≈ ALIAKSANDR, MYKOLA ≈ NIKOLAI ≈ MIKALAI и др.; для фамилий правило первой буквы осталось).
- **Задачи**: всегда Юле «Фірма для ZUS» (срок — сегодня, в день создания заявки); при слабом совпадении ещё Оле «Перевірити дубль».
- **Дубли видны текстом**: схожие карточки — вычисляемое поле «Схожі картки» (через `sudo`: имя, фирма, архив), потому что в Odoo 19
  связанные записи чужих фирм в many2many отсеиваются по выбранным фирмам. «Це та сама людина»: схожая одна — берётся она; несколько —
  в поле «Номер зі списку» указывается номер из текста.
- **Выбор фирмы**: на форме Виїзда — плашки фирм (кликабельный `statusbar` по полю «Фірма для ZUS», фирмы с флагом `workset_dispatch_firm`).
  Один клик сохраняет выбор, и запись создаёт карточку: в выбранной фирме, имя «ФАМИЛИЯ ИМЯ | позначка» одним пробелом, телефон, страна,
  дата рождения, должность (профессия), ответственный HR; **договор, ставка, аналитика не ставятся**. Карточка этого человека уже есть в
  выбранной фирме (в том числе в архиве) — возвращается из архива, дописываются только пустые поля. Заявка связывается с карточкой
  стандартным `employee_id` (как «Створити співробітника»), этап «Оформлено» (последний, «найнятий»), Оле — задача «Договір і ставка».
- **Контакт**: карточка того же человека в другой фирме — новая карточка получает тот же `work_contact_id`; иначе ищется существующий
  контакт человека (не компания, не контакт карточки другого человека, не пользователь; тот же телефон или то же имя); один кандидат — берём,
  несколько — стандарт Odoo и строка «перевір контакт» в задаче Оле.
- **Кнопки**: «Створити картку» (если фирма выбрана), «Це та сама людина» / «Нова людина» (Оля, при «Перевірити дубль»),
  «Не наш / не поїхав» (Юля или Оля → «Не поїхав» и архив, карточки нет).
- **Права**: создать карточку может только `hr.group_hr_user` (иначе `AccessError`); импорт и отмена — `hr.group_hr_manager` / `base.group_system`.
- **Отмена и возврат**: `workset_dispatch_cancel(deal_ids)` — Виїзди сделок, ставших lost или удалёнными, в состоянии «чекає фірму / перевірити дубль»
  → «Не поїхав» и архив (`workset_cancel_source` = `pipedrive`). Если такая сделка снова пришла на этап и не lost — Виїзд **возвращается**
  (решение `reopened`, новая задача Юле). Отменённый кнопкой («позначила людина») не возвращается. Открытый Виїзд с перенесённой «Датой отправки» —
  дата обновляется (решение `updated`).
- **Экраны**: «Співробітники → Виїзди» (список, канбан, форма; фильтры «Не скасовані» — по умолчанию, «Чекають фірму», «Перевірити дубль»,
  «Оформлено», «Не поїхав»; группировки по фирме, замовнику, месяцу выезда). Действие открывается с `active_test: False`: архив вакансии
  архивирует её заявки (`hr_recruitment/models/hr_job.py`), и открытые Виїзди не должны пропадать. На карточке работника — смарт-кнопки «Виїзди» и «Угода Pipedrive».
- Язык интерфейса — украинский, `i18n/ru.po` — русский (для Оли), собирается `tools/odoo_addon_po.py` из `tools/lib/workset_dispatch_ru.json`.

## Метод workset_dispatch_import
Права: `hr.group_hr_manager` или `base.group_system`, иначе `AccessError`. Идемпотентен по `deal_id`. Один элемент:
`deal_id`, `person_id`, `last_name`, `first_name` (латиница или кириллица; транслитерация по гражданству: Украина — КМУ 2010, Беларусь —
белорусская паспортная, прочие — украинская; при транслитерации `workset_name_check` = «Звірити ім'я з паспортом»), `phone`, `phones`,
`birthday`, `citizenship` (подпись), `profession` (подписи через запятую), `vacancy_label` (код `WS-…` ищет модуль по полю кода вакансии),
`org_id`, `org_name`, `departure_date`.

Ответ по каждой сделке: `deal_id`, `decision`, `firms`, `created`, `applicant_id`, `no_job`.
`decision`: `created` — повторов нет; `strong` — тот же контакт, либо основной телефон и схожее имя (в `firms` — позначки фирм этих карточек);
`weak` — совпало только имя, либо телефон при другом имени (`check_dup`); `no_job` — вакансии по коду `WS-XX-ММДД-NN` нет (пусто, не ошибка);
`exists` — Виїзд сделки уже есть (в том числе в архиве); `updated` — у открытого Виїзда обновлена дата; `reopened` — отменённый
через Pipedrive Виїзд возвращён; `skipped` — не хватает данных; `error` (причина — в журнале Odoo: тип и начало сообщения). При `dry_run=True` ничего не пишется (это «прогон вхолостую»).

## Поля (все свои — с префиксом `workset_`)
- `hr.applicant`: `workset_pd_deal_id` (уникален среди заявок, в том числе архивных), `workset_pd_person_id`, `workset_departure_date`,
  `workset_birthday`, `workset_country_id`, `workset_profession`, `workset_customer_id`, `workset_customer_name`, `workset_firm_id`,
  `workset_state` (`wait_firm`, `check_dup`, `done`, `cancel`), `workset_dup_employee_ids`, `workset_same_employee_ids`,
  `workset_pick_no`, `workset_dup_text`, `workset_same_text`, `workset_cancel_source`, `workset_name_check`, `workset_pd_url`, `workset_firm_activity_id`, `workset_dup_activity_id`.
- `hr.employee`: `workset_pd_deal_id`, `workset_pd_person_id`, `workset_dispatch_count`, `workset_pd_url`.
- `res.company`: `workset_dispatch_firm` («Фірма для ZUS»), `workset_name_suffix` («Позначка в імені»).

## Параметры `ir.config_parameter` (пишет `tools/odoo_dispatch.js --seed`, ключей Pipedrive здесь нет)
| Параметр | Смысл |
|---|---|
| `workset_dispatch.pd_domain` | адрес Pipedrive — только для ссылки на сделку |
| `workset_dispatch.since` | дата: отправки раньше неё берутся только поштучно (`--backfill`); читает инструмент |
| `workset_dispatch.skip_org_ids` | id организаций Pipedrive через запятую, чьи сделки пропускаются (партнёры вне периметра); по умолчанию не задан; читает инструмент |
| `workset_dispatch.max_per_run` | сколько новых за один проход; читает инструмент |
| `workset_dispatch.job_code_field`, `.job_partner_field` | имена полей вакансии: код и заказчик (созданы через API, читаются мягко) |
| `workset_dispatch.firm_user_id`, `.hr_user_id` | кому задачи «Фірма для ZUS» и «Договір і ставка» / «Перевірити дубль»; HR-ответственный новых карточек |
| `workset_dispatch.recruit_company_id` | фирма заявок, если у вакансии нет фирмы |

## Установка и обслуживание
1. Папку модуля — в репозиторий Odoo.sh (`node tools/odoo_sh_push.js --module workset_dispatch`, делает coordinator); сборка ветки.
2. `node tools/odoo_dispatch.js --target copy --install --apply`, затем `--seed --apply`, `--verify`.
3. Проход Pipedrive → Odoo — `--pull` (таймер на VPS каждые 15 минут), вхолостую — `--preview --since …`, прошлые — `--backfill --deals …`.

## Откат
Таймер на VPS выключить (читать сделки перестанет). Созданные модулем заявки найти по `workset_pd_deal_id > 0` и архивировать (карточки
не удаляются: они уже живая часть учёта). Модуль можно удалить из «Додатків» — свои поля уйдут вместе с ним, стандартные заявки и
карточки останутся.

## Что известно заранее
- Стандартный переход заявки в «найнятий» этап сам уменьшает `no_of_recruitment` вакансии (`hr_recruitment/models/hr_applicant.py`);
  других записей в `hr.job` заявки и найм не делают (сайт слушает `name`, `active`, `company_id` и поля `x_*`).
- Листы зарплаты (`hr_payroll`, Enterprise) строятся по договорам: у карточки без договора версия без `contract_date_start`.
