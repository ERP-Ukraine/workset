# workset_profit — «Прибутковість ліній» (М3, круги 1–5б)

Модуль Odoo 19.0 для репозитория Odoo.sh `ERP-Ukraine/workset`. Здесь только устройство (модели, расчёт, экраны, виды, права, плановое);
данные — разметку аналитики, «Хто платить», карты DKV и их периоды, транзакции DKV — пишет инструмент штаба через API. Сумм, имён людей и
заказчиков в коде нет. Круг 1 — расчёт «лінія × місяць» и простые виды; круг 2 — три экрана по макетам владельца (ниже, «Экраны»).

## Что считает
Хранимый итог `workset.profit.month` — «лінія × місяць» (и строки компании), цепочка владельца «частка → житло → авто → паливо →
інструмент → чисто»:

| Поле | Что | Откуда |
|---|---|---|
| `hours_total`, `hours_rate`, `hours_no_rate` | годин всего / со ставкой / без ставки | табели месяца |
| `share` | частка WorkSET | часы × `net_share` ставки на день (ставка меняется внутри месяца — отрезки); «Фікс за місяць» — `fixed_month` × доля часов пары в месяце − бонус офиса × часы |
| `car_rent` | оренда авто (наш доход, в «чисто») | часы × `car_rent_share` ставки |
| `fund_in` | у фонд працівників (не наше) | часы × `worker_fund_share` ставки |
| `housing`, `auto`, `fuel`, `tool`, `transport` | наши расходы линии (минус) | аналитика + DKV по разметке, кто платит — «мы» (или заказчик) |
| `housing_customer` | житло (вирахував замовник) — минус, в «чисто» | правило жилья линии «Ставок» с «Хто платить» = заказчик: сумма × единица (ниже) |
| `net`, `net_per_hour` | **чисто** €/міс и €/год (на часы со ставкой) | частка + оренда авто + наши расходы (с жильём, которое вычел заказчик); до ZUS и общих |
| `zus_amount`, `office_amount`, `remain`, `remain_per_hour` | доли ZUS, PIT-4 и загальних фірм (минус), **залишається** €/міс и €/год (круг 4) | загальні месяца × часы строки ÷ все часы табеля (раздел «Залишається WorkSET») |
| `partner_paid` | з грошей лінії (партнёр) | расходы, где платит партнёр, и вид «Гроші лінії» |
| `fund_paid`, `fund_left` | з фонду працівників; остаток месяца = у фонд + з фонду | расходы, где платит фонд |
| `housing_buffer` | буфер житла — отложено на жильё из оплаты заказчика (журнал WS «Передача ліквідності»); справочно, не доход, не в «чисто» | вид «Буфер житла» |
| `amount` | сумма строки компании | «Не розподілено», «Офіс», «Власник», «Не враховано», рахунки DKV |
| `aal_amount`, `dkv_amount` | служебное для сверки | сколько в строке из аналитики и из транзакций DKV |

Строки (`row_kind`): `line` — линия; `noline` — часы заказчика без линии; `unallocated` — «Не розподілено» по статье (с подсказкой вида), по
виду без линии, «DKV: рахунок без транзакцій», «DKV різниця» (счёт ≠ его транзакциям), «DKV: картка без періоду», «Перевезення без
прибуттів»; `office` — «Офіс» (по статье или
карте DKV); `owner` — «Власник» по статье аналитики (узел «… / Owners», решение 05.11 R09); `ignore` — «Не враховано»; `dkv` — счета DKV, вместо
которых считаются их транзакции. «Чисто» строки компании: «Офіс», «Власник», «Не розподілено» — сумма (кроме буфера жилья и денег линии без
линии); «Не враховано» и `dkv` — 0.

## Откуда берёт
- **Часы** — `account.analytic.line`: проект есть, счёта (`general_account_id`) нет, работник есть, часы > 0; фирмы — периметр «Ставок»
  (`workset_rates.out_of_perimeter_company_ids`). Человек — `hr.employee.work_contact_id` (та же связь «карточка → контакт ставки», что в
  «Ставках»: `_pair_hour_rows`, «Працюють»); по имени не сопоставляем — карточка с другим контактом даёт часы «без ставки». Заказчик —
  `project_id.partner_id.commercial_partner_id`, линия — `workset.line`, у которой заказчик в `customer_ids` (первая по порядку линий).
- **Частка** — `workset.rate._plan_at(pairs, day)` на первый день каждого отрезка месяца между новыми ставками пары (смена ставки
  внутри месяца). Нет ставки — `None`, часы — в `hours_no_rate`. Ключей `worker_fund_share` / `car_rent_share` в ответе нет — 0.
- **Расходы** — `account.analytic.line` с `general_account_id` и статьёй (`account_id`) под корнями плана рекрутинга: параметр
  `workset_profit.root_plan_ids` (id через запятую); нет параметра — корни узлов линий (`workset.line.plan_ids`). Сумма — в EUR (курс даты
  строки). Месяц (`calc.service_period`): у строки счёта есть `deferred_start_date` / `deferred_end_date` (поля бухгалтерии, если есть в
  сборке), параметр `workset_profit.split_by_period` не «ні» и **у счёта нет проводок отсрочки Odoo** (`deferred_move_ids` /
  `deferred_original_move_ids`) — по дням периода (центы раскладываются без потерь); иначе — по дате строки. Проводки отсрочки Odoo уже
  разносят сумму по месяцам своими датами — делить счёт с ними значило бы считать дважды (известный сдвиг без периода: аренда двух месяцев
  одним счётом видна в месяце счёта).
- **Кто платит** — житьё: `workset.line.housing._housing_at(линия, заказчик, день)` «Ставок» (`we_buffer`, `customer` — мы; `partner` —
  партнёр; `worker_fund` — фонд; вид правила не важен: «Житло не наше» с «Хто платить» = фонд / партнёр — тоже «З фонду» / «З грошей
  лінії», не наше «чисто»); авто, паливо, інструмент, перевезення — `workset.line.cost.rule`
  (правило заказчика точнее правила линии; нет правила — мы).
- **Житло, которое вычитает заказчик** (`housing_customer`, `calc.customer_housing`): на каждый день с часами у заказчика линии — правило
  `_housing_at`; «Хто платить» = заказчик и сумма есть → по единице правила: «€ за місяць за особу» (`month_person`, «Ставки» 06.11) —
  сумма за человека в месяц (люди с часами в месяце у этого заказчика; один раз — в первый день, когда правило действует); «€ за місяць
  (об'єкт)» (`month`) — по `calc.MONTH_UNIT` (одна строка; сейчас `object`): одна сумма в месяц на «линия × заказчик»;
  «€ за добу за особу» — × человеко-дни с часами, «€ за годину житла» — × часы, «% з оплати» — % от
  часы × «Платять нам». Если такой вычет ещё и стоит строкой в аналитике (кредит-нота, скидка) — её размечать `ignore`, иначе второй раз.
- **DKV** — `workset.dkv.txn` (брутто EUR — так проведено в книгах) → период карты на дату транзакции: линия → «Паливо» по «Хто платить»,
  офис → строка «Офіс» карты, перевезення → между линиями по прибытиям; периода нет — «Не розподілено». Счёт с транзакциями — привязанными
  полем `move_id` или (поле пусто) по номеру счёта DKV `invoice_no` = «Референс» (`ref`) счёта: его аналитика — строка `dkv`, не второй раз;
  разница «аналитика счёта − брутто его транзакций» (частичная загрузка) — в месяц пропорционально доле месяца строкой «Не розподілено: DKV
  різниця» (`calc.dkv_bill_entries`). Счёт DKV без транзакций (разметка `dkv_bill`) — «Не розподілено: DKV». Транзакции без счёта в Odoo
  (API, счёт ещё не выставлен) — по линиям; в сверке — «Транзакції DKV без рахунку в Odoo: N, сума», а если в месяце есть и счёт DKV без
  транзакций — предупреждение о возможном двойном счёте (привязать транзакции к счёту).
- **Перевезення людей** (решение владельца 06.11 «перевозка: на линию») — транзакции карт с периодом `transport` и аналитика вида
  `transport` без линии делятся между линиями по числу прибытий месяца. Прибытие — начало периода работы человека по табелям (разрыв между
  соседними датами > 45 дней — новый период, как `STINT_GAP_DAYS` в `tools/lib/odoo_arrivals.js`); человек — склеенные карточки, как
  `buildPersons` там же (`calc.glue_people`: общий телефон, кроме записанного у двух и более разных имён; одинаковое имя без приписки фирмы
  « | TF» / « | PA»; общий рабочий контакт) — карточки одного человека в разных фирмах не дают нового прибытия; линия — по заказчику первого
  дня периода (больше часов). Прибытий нет — «Не розподілено: перевезення без прибуттів». Кто платит — правило «Хто платить» вида
  `transport` линии. Ставка же ищется по-прежнему по контакту карточки (как в «Ставках»).

## Разметка аналитики (`workset.profit.analytic.map`)
Ключи правила — узел плана, статья аналитики, счёт, контрагент; правило берёт сумму, когда совпадают **все** заполненные ключи.
Точнее: контрагент > статья > счёт > узел (ключи складываются), затем глубже узел, позже «З». Линии в правиле нет — линия по узлу статьи
(глубже — точнее) или по заказчику (правила или контрагент статьи). Без правила — «Не розподілено» по статье и счёту; подсказка вида по
имени (`calc.kind_hint`: Жилье / Житло, Жилье + Буфер, Топливо / Паливо, Инструмент / Спецодежда, Транспорт / Вождение / Лизинг) — только
в форме разметки и в имени строки «Не розподілено», считает разметка.

| Вид | Подпись | Куда идёт сумма |
|---|---|---|
| `housing` | Житло | линия: «Житло» (мы) / «З грошей лінії» (партнёр) / «З фонду» — по правилу житла линии «Ставок» |
| `housing_buffer` | Буфер житла (довідково) | линия: «Буфер житла», в «чисто» не входит (часть оплаты заказчика через «Передача ліквідності») |
| `fuel` | Паливо | линия: «Паливо» / партнёр / фонд — по «Хто платить» |
| `tool` | Інструмент і спецодяг | линия: «Інструмент» / партнёр / фонд |
| `auto` | Авто | линия: «Авто» / партнёр / фонд |
| `transport` | Перевезення людей | линия: «Перевезення»; без линии — между линиями по прибытиям |
| `dkv_bill` | Рахунок DKV | есть транзакции по счёту — строка `dkv` (не второй раз); нет — «Не розподілено: DKV» |
| `partner` | Гроші лінії (партнер) | линия: «З грошей лінії» (узлы «… / Partners») |
| `owner` | Власник | строка «Власник · <статья>» (узел «Recruting / Owners»), не линия |
| `office` | Офіс | строка «Офіс · <статья>» |
| `ignore` | Не враховувати | строка «Не враховано»: в сверке, не в «чисто» (выручка, зарплата — они уже в частке ставок) |

Вид линии без линии — «Не розподілено (… без лінії)». Пример разметки: узел линии → `ignore` (выручка и зарплата), счёт «Топливо» в
зарплате → `fuel` (счёт точнее узла), статья «Жилье | Расход | …» → `housing`, поставщик DKV → `dkv_bill`, узел Owners → `owner`;
оренда авто в аналитике (доход линии вроде SoMa) → `ignore`: аренду уже считает ставка (`car_rent` = часы × `car_rent_share`), иначе она
войдёт в «чисто» второй раз.

## Экраны (круг 2, макеты A, B, C)
Меню «Прибутковість»: **Огляд** (первым) → **Лінії × місяці** → «Хто платить» → «Картки DKV» → «Транзакції DKV» → «Розмітка аналітики» →
«Рядки розрахунку» (список строк круга 1). Каждый экран — client action OWL (`static/src/js/profit_screens.js`, шаблоны
`static/src/xml/profit_screens.xml`, стиль `static/src/scss/workset_profit.scss`) и **один** вызов сервера (`models/workset_profit_screens.py`);
числа, цвета тревог, ряды графиков и геометрию водопада считает сервер (`models/calc.py`), JS только показывает и переходит.

| Экран | Метод | Что показывает | Откуда числа |
|---|---|---|---|
| A «Огляд» (`workset_profit.overview`) | `profit_overview(month, kind, date_to)` (круг 5 — период, ниже) | месяц (по умолчанию — последний закрытый); пять итогов месяца: Годин, Частка WorkSET € год, «Житло, авто, паливо, інструмент» € год, Чисто € год, Чисто за місяць €; чипы тревог; плитки линий; «Чисто по місяцях» (все линии вместе жирно, каждая тонко); «Куди йде частка» | строки `workset.profit.month` вида «лінія» месяца (`calc.totals`: частка + витрати = чисто до цента; € год — на часы со ставкой); плитка — строка линии как есть (`net`, `net_per_hour`), стрелка — к `net_per_hour` прошлого месяца |
| B картка лінії (`workset_profit.line_card`) | `profit_line_card(line_id, month, kind, date_to)` | месяц со стрелками; пять итогов линии; водопад «Частка → + Оренда авто → − Житло → − Житло (вирахував замовник) → − Авто → − Паливо → − Інструмент → − Перевезення → = Чисто» (€ над столбцом, € год под ним; нулевых шагов нет); «Хто платить»; «Не в нашому чисто»; «Чисто по місяцях»; «Рядки за <місяць>» | строка линии месяца (`calc.chain_steps`: шаги до «чисто» дают сохранённое «чисто» до цента; `calc.waterfall`); «Хто платить» — правило жилья «Ставок» (`_housing_at`) и правила «Хто платить» на последний день месяца, паливо — ещё карты DKV линии; строки — тот же разклад, что в пересчёте (`_month_entries`), каждая открывает свои записи (аналитика, транзакции DKV, табели) |
| C «Лінії × місяці» (`workset_profit.matrix`) | `profit_matrix(date_from, date_to)` | линии × месяцы периода (по умолчанию январь — последний закрытый, не больше 24), итог периода, «€ год» / «€ за місяць»; клик — всплывающая цепочка месяца и «Відкрити рядки» (карточка B); ниже серым — «Не розподілено», «Власник <статья>», «Звірка з аналітикою» | строки линий (`net_per_hour`, `net`), цвет — `calc.cell_tone`: красное — чисто < 0, жёлтое — чисто € год упало к прошлому месяцу больше порога `workset_profit.drop_alert` (нет — 1,5); итог периода — сумма чисто ÷ сумма часов со ставкой |

Чипы «Огляду» (нет числа — нет чипа; клик — список строк расчёта, число на чипе = строки списка): «Не розподілено» € (чисто строк «Не
розподілено»), «Години без ставки», «Години без лінії» (часы заказчиков без линии), «Житло не в своєму місяці» (`calc.housing_shift`: жильё
есть, а часов нет, или жильё на час больше `workset_profit.housing_shift_ratio` × медианы других месяцев линии, нет параметра — 2; типично —
счёт за два месяца одной строкой), «Власник <статья>» € каждого, «Звірка» (зійшлася / розбіжність — текст сверки). Сверку экраны не
пересчитывают: её итог пишет пересчёт (и «Звірити») в `workset.profit.check` «Звірка місяця».

Переходы: плитка «Огляду» и полоса «Куди йде частка» → карточка линии этого месяца; клетка C → цепочка → «Відкрити рядки» → карточка; кнопка
строки линии в списке «Рядки розрахунку» и в карточке строки (`action_open_card`) → карточка. Карточка помнит последнюю линию и месяц у
пользователя (браузер) — после перезагрузки страницы открывается она.

**Каждое число открывает свои записи** (круг 3в, слово владельца 06.11 «экраны: должно быть все кликабельно»). Сервер отдаёт у элемента
описание `open` (модель, домен, заголовок, контекст `create: False`; `res_id` — форма одной записи), собирается оно в одном месте
(`_open`, `_line_open`, `_kind_open`, `_ts_domain` в `workset_profit_screens.py`), JS только выполняет (`openList`); новых методов на клик нет.

| | Житло, авто, паливо, інструмент | строки линий месяца с расходами (оренда авто, житло, авто, паливо, інструмент, перевезення ≠ 0) |
| A, «Куди йде частка» | сегмент полосы | записи этого вида линии за месяц (как шаг водопада B); «чисто» — строка линии; название линии — карточка, как раньше; легенда — без клика |

- **ZUS і PIT-4** — по фирмам (`calc.zus_groups`): фирма · ZUS · PIT-4 · рахунків N · разом €; клик — счета этой фирмы и вида за период
  (ячейка ZUS — её счета ZUS, PIT-4 — PIT-4, «разом» — все); итог — все счета периода. Ниже, если есть: «ZUS без мітки місяця» (уже в
  сумме — месяц по дате проводки) и «з міткою поза вікном» (справочно: не входят ни в один месяц; счета, проведённые в месяцах периода,
  `_contrib_outside_moves`).
- **Загальні фірм** — по статьям (`calc.office_split`, `calc.office_groups`): статья аналитики (под ней — её план, например
  «…/Расходы»), карты DKV с целью «офіс» — одной строкой «DKV · офіс»; стаття · сума € · записів N (строк расчёта «Офіс»); клик — эти строки
  (ровно те, что вошли в число: строка «Офіс» целиком из аналитики счетов ZUS / PIT-4 не входит, частичная — её сумма без этой
  аналитики, `calc.office_rows_in`); итог; справочно «Рахунки ZUS / PIT-4 в «Офісі»» (`office_dup`), если ≠ 0.
- **Як поділено** (`calc.overhead_how`): часов табеля за период, ZUS і PIT-4, загальні и вместе на час (до 4 знаков); на B — «Частка
  лінії: N год × X € = Y €» (X — доля ÷ её часы; «≈», если произведение с округлённым X не даёт долю до цента), на A — «Частка ліній»;
  круг 5б — ниже строка **«На годину зі ставкою»**: та же доля ÷ часы со ставкой, до цента (`calc.overhead_how`, `part.rate_ph` — то же
  правило, что `remain_totals`); на A — «(як на екрані)»: ровно число «ZUS і загальні € год», по которому кликнули (если все месяцы
  пересчитаны); на B — доля линии на её часы со ставкой (шаги водопада показывают ZUS и загальні отдельно); подсказка «версія 1: за
  годинами табеля».
- **Откуда записи**: пересчёт пишет в итог месяца `workset.profit.overhead` поле **`breakdown`** (19.0.4, `calc.overhead_breakdown`): вид и
  сумма каждого счёта ZUS / PIT-4 и аналитика этих счетов в строках «Офіс» по статьям — окно не ищет счета и не разлагает месяц заново (A и
  C за год — без разкладов). Месяц, пересчитанный до 19.0.4 (поля нет), окно собирает само: счета — `_contrib_moves`, статьи — разклад
  месяца (только если `office_dup` ≠ 0) — медленнее; после установки 19.0.4 — `--recalc --from 2026-01`.
- **Подпись буфера** (справочно, не в «чисто»): «Відкладено на житло з оплати замовника — не в чисто» — буфер наполняется из оплат
  заказчика (журнал WS «Передача ліквідності»), не из оплаты людей.

## Модели и виды
- `workset.profit.month` — «Рядки розрахунку» (до круга 2 — «Лінії × місяці»): список (кнопки «Перерахувати» — редактор, «Звірити»;
  группировка по месяцу; кнопка строки линии — карточка B; рядки пишет только код), сводная (строки × месяцы, «Чисто»), график, карточка
  строки (нулевое скрыто).
- `workset.profit.overhead` — «ZUS і загальні місяця» (круг 4, раздел выше): пишет пересчёт, читают экраны и сверка; один на месяц.
- `workset.profit.check` — «Звірка місяця»: итог сверки месяца (сошлось, текст), пишет пересчёт и «Звірити»; читают экраны.
  Одна запись на месяц: `models.Constraint('UNIQUE(month)')`; запись — «есть — обновить, нет — создать» под замком месяца пересчёта.
- `workset.line.cost.rule` — «Хто платить»: линия, заказчик (необязательно), вид (`auto`, `fuel`, `tool`, `transport`), кто платит (`we`,
  `partner`, `worker_fund`, `customer`), с–по; одно правило на «линия × заказчик × вид» на дату; история изменений.
- `workset.dkv.card` + `workset.dkv.card.period` — «Картки DKV»: номер (уникальный), порядковый № в кабинете DKV, машина (`fleet.vehicle`);
  периоды «лінія [+ замовник] / офіс / перевезення людей» с датами (один на дату), правка на месте в карточке.
- `workset.dkv.txn` — «Транзакції DKV»: дата, карта, страна, город, группа товара, количество, нетто и брутто EUR, номер счёта DKV, счёт
  поставщика Odoo (необязательно), источник `pdf` / `api`, «Ключ рядка» (уникальный — повтор записи не множит).
- `workset.profit.analytic.map` — «Розмітка аналітики» (выше).

## Пересчёт и сверка
- `workset.profit.month.profit_recompute(date_from=None, date_to=None)` — месяцы периода (нет — 3 последних с текущим; не больше 36 за
  раз): строки месяца заново (старые удаляются), затем сверка; → `{'months', 'rows', 'verify'}`. Только редактор прибутковости или
  администратор; `sudo` — только внутри пересчёта и сверки. Кнопка «Перерахувати» — месяцы выбранных строк или 3 последних.
- Плановое «Прибутковість: щоночі» (`data/ir_cron.xml`) — 23:00 UTC (после «Ставки: щодня» 22:15 UTC), 3 последних месяца, включено.
- `_verify(month)` («Звірити»; для инструмента — публичный `profit_verify(date_from, date_to)`, только чтение, право — читать итог) —
  сумма денег аналитики в строках = аналитика плана за месяц (та же выборка, части периодов и курс) до цента; **отдельный подсчёт**
  аналитики плана, датированной месяцем, — `_read_group` по фирмам (не через `_analytic_items`), в валюте фирмы — равен тем же строкам в
  расчёте (ловит строку, которую расчёт потерял); деньги DKV в строках = минус брутто транзакций месяца; в каждой строке столбцы дают её
  сумму; расхождение — текстом с числами. Справочно в тексте: сколько периоды услуги перенесли между месяцами; транзакции DKV без счёта в
  Odoo (N, сумма) и предупреждение о возможном двойном счёте, если в месяце есть и счёт DKV без транзакций.

## Права
Привилегия «Прибутковість» (раздел кадров формы пользователя): «Перегляд» — читает всё и единственная видит меню и экраны; «Редактор»
(включает «Перегляд») — правит «Хто платить», карты и транзакции DKV, разметку, пересчитывает; удаляет — системный администратор (периоды
карты — и редактор, правка на месте). Итог `workset.profit.month` и «Звірку місяця» пишет только код. «Перегляд» читает линии «Ставок»;
аналитику, счета и машины — по своим правам бухгалтерии и автопарка (строки итога несут готовое имя; строки карточки линии без права на
аналитику — без перехода).

## Установка
1. Сначала `workset_rates` (19.0.3 — с фондом працівників и арендой авто в `_plan_at`), затем этот модуль: папка — в репозиторий Odoo.sh
   (ветка копии → сборка и тесты → `main`); помощник штаба `node tools/odoo_sh_push.js --module workset_profit` (план; выкладывает coordinator).
   Зависимости: `workset_rates`, `fleet` (приложение «Автопарк»).
2. Установка и обслуживание — инструмент штаба `tools/odoo_workset_profit.js` (`--target copy|prod` обязателен; без `--apply` — план,
   код 3; прод — только с `--confirm-prod <база>` и вне пн–пт 9–17 по Киеву):
   `--install` — обновить список модулей, установить / обновить `workset_profit`, дождаться installed;
   `--seed [--file <json>] [--include-unconfirmed]` — посев из `tools/lib/workset_profit_seed.json`: разметка, «Хто платить», карты DKV с
   периодами, `workset_profit.root_plan_ids` (если пуст), учётка ключа — в группу «Перегляд»; сначала сверка имён по id (не сходится —
   стоп, ничего не пишет); пишет только пустые поля, остальное — «розбіжність» в плане; `sure: low` и неподтверждённые карты — только с
   `--include-unconfirmed`; карта без номера не создаётся; правила жилья (`housing_changes`) — данные «Ставок», не пишет;
   `--recalc --from ГГГГ-ММ --to ГГГГ-ММ` — пересчитать месяцы (`profit_recompute`) и показать сверку каждого;
   `--verify [--from ГГГГ-ММ --to ГГГГ-ММ]` — только чтение: модуль, виды, меню и экраны, группы, плановое, сверка месяцев (`profit_verify`);
   `--dkv-import [--from ГГГГ-ММ --to ГГГГ-ММ]` — транзакции DKV из PDF счетов (раздел «Транзакції DKV: імпорт з PDF»).
3. «Перерахувати» (или `--recalc`) → «Звірити» (или `--verify`): строки «Не розподілено» — что ещё разметить; затем «Огляд».
4. Обновление до **19.0.5** (круг 5б, поле `card_groups`) и до 19.0.4 (`breakdown`): после `-u` — обязательно `--recalc --from 2026-01`
   (ночной пересчёт берёт только 3 месяца): до него карточка линии за период и окно «Що входить» собирают месяцы сами — числа те же, но
   медленнее (год B — секунды).

**Порядок выкладки на прод** (важно): сначала «Ставки» с единицей правила жилья `month_person` «€ за місяць за особу» (их коммит
721c535e4) и пересев в эту единицу правил жилья заказчика, который вычитает жильё с каждого человека (имя — в посеве «Ставок», не здесь) — затем `workset_profit` (`--install`, `--seed`) и пересчёт (`--recalc`). Иначе
«€ за месяц с человека» лягут единицей `month`, а её модуль считает одной суммой на объект (`calc.MONTH_UNIT = 'object'`) — житло, которое
вычитает заказчик, получится в разы меньше. После любой правки единиц жилья — пересчитать затронутые месяцы.

## Транзакції DKV: імпорт з PDF
Карты №1–9 в посеве хранятся маской «…NNN» (последние 3 цифры) в обязательном уникальном поле `number`: полный номер платёжной карты не
храним нигде. Импорт — инструмент штаба `tools/odoo_workset_profit.js --dkv-import` (разбор PDF — `tools/dkv_pdf_txns.py`, Python +
pdfplumber через uv; перший запуск — з мережею (кеш uv завантажує pdfplumber і Python 3.13), далі без мережі); модуль сам PDF не читает.
1. **Счета DKV в Odoo** — счёт поставщика, проведён, партнёр DKV, «Референс» = номер счёта DKV вида `26/…/000`, PDF счёта во вложении
   (полный «Invoice-…pdf»: сводка по странам и под-счета со строками транзакций).
2. **План** — `--dkv-import --from ГГГГ-ММ --to ГГГГ-ММ` (без `--from` — с января текущего года; без `--apply` — только план, код 3):
   по каждому счёту — строк, брутто EUR против суммы счёта Odoo, новых / уже есть / без картки; по каждой карте — строк и сумма; строки
   карт, которых в Odoo нет (по `seq`), — «без картки» с суммой (не пишутся). Карта — по `seq` (= «VOZIDLO» в PDF) среди активных; последние
   3 цифры номера из PDF ≠ маске карты — стоп, ничего не пишет (карта не та). PDF другого счёта или нечитаемый — тоже стоп.
3. **`--apply`** — запись `workset.dkv.txn` пачками (`source = pdf`, `invoice_no` = «Референс» счёта, `move_id` = счёт, брутто и нетто
   EUR, страна кодом ISO, город, товар, количество, нотатка «под-счёт · станция · время» — без номера карты); ключ строки
   `ref = pdf:<счёт>:<под-счёт>:<станция>-<транзакция>-<код товара>[-N]` — повторный запуск не множит (`-N` — одинаковые строки одной
   транзакции). id созданного — в снимке `data/bak/odoo-workset-profit-dkv-…json` (откат — удалить эти записи). Затем повторный план пуст.
4. **`--recalc`** затронутых месяцев — транзакции идут в «Паливо» линий по периодам карт, аналитика счёта вдруге не считается.

Что не импортируется: счёт, к которому приложена только сводка без строк («E-SUMMARY…pdf», в плане — «рахунок без детального PDF»);
счёт без PDF; строки карт, которых нет в Odoo; счёт, где помощник не разобрал строку или строки карты ≠ «TOTAL» карты, — целиком
(«⛔ рахунок …: нерозібрані рядки — пропущено»; `--apply` при таком счёте — код 1, с `--skip-bad` пропускается только он): иначе после
починки разборщика повторный импорт сдвинул бы суффиксы `-N` ключей. Такие счета остаются в «Не розподілено: DKV» — до полного PDF,
починки разборщика или до API DKV.
Кредит-ноти DKV (`in_refund`) не імпортуються.

Как узнать расхождение: в плане у счёта «≠ счёт Odoo … — DKV різниця …» (брутто строк PDF ≠ сумме счёта в книгах); после `--recalc` —
строка «Не розподілено: DKV різниця» месяца. Помощник сверяет и сам (строки ⚠ в плане): строки карты = «TOTAL» карты, строки под-счёта =
его сумме в сводке, под-счета = «Celková částka»; строка, которую он не разобрал, — тоже ⚠ с датой. Под-счёт не в EUR (PLN): EUR строк —
из столбца PDF «в платёжной валюте», а если он не сходится со сводкой — пропорцией EUR-итога сводки до цента (разница — в последнюю строку).
Если у двух карт совпадут хвосты, уникальность `number` откажет — тогда расширить маску до 4 цифр (посев и импортёр вместе).
