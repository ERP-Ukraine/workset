# workset_profit — «Прибутковість ліній» (М3, круг 1)

Модуль Odoo 19.0 для репозитория Odoo.sh `ERP-Ukraine/workset`. Здесь только устройство (модели, расчёт, виды, права, плановое); данные —
разметку аналитики, «Хто платить», карты DKV и их периоды, транзакции DKV — пишет инструмент штаба через API. Сумм, имён людей и заказчиков
в коде нет. Красивый экран (плитки линий, график, цепочка с кликом до проводок) — круг 2, после выбора макета владельцем.

## Что считает
Хранимый итог `workset.profit.month` — «лінія × місяць» (и строки компании), цепочка владельца «частка → житло → авто → паливо →
інструмент → чисто»:

| Поле | Что | Откуда |
|---|---|---|
| `hours_total`, `hours_rate`, `hours_no_rate` | годин всего / со ставкой / без ставки | табели месяца |
| `share` | частка WorkSET | часы × `net_share` ставки на день (ставка меняется внутри месяца — отрезки); «Фікс за місяць» — `fixed_month` × доля часов пары в месяце − бонус офиса × часы |
| `car_rent` | оренда авто (наш доход, в «чисто») | часы × `car_rent_share` ставки |
| `fund_in` | у фонд працівників (не наше) | часы × `worker_fund_share` ставки |
| `housing`, `auto`, `fuel`, `tool`, `transport` | наши расходы линии (минус) | аналитика + DKV по разметке, кто платит — «мы» (или заказчик) |
| `housing_customer` | житло (вирахував замовник) — минус, в «чисто» | правило жилья линии «Ставок» с «Хто платить» = заказчик: сумма × единица (ниже) |
| `net`, `net_per_hour` | **чисто** €/міс и €/год (на часы со ставкой) | частка + оренда авто + наши расходы (с жильём, которое вычел заказчик); до ZUS и общих |
| `partner_paid` | з грошей лінії (партнёр) | расходы, где платит партнёр, и вид «Гроші лінії» |
| `fund_paid`, `fund_left` | з фонду працівників; остаток месяца = у фонд + з фонду | расходы, где платит фонд |
| `housing_buffer` | буфер житла — справочно, не доход | вид «Буфер житла» |
| `amount` | сумма строки компании | «Не розподілено», «Офіс», «Власник», «Не враховано», рахунки DKV |
| `aal_amount`, `dkv_amount` | служебное для сверки | сколько в строке из аналитики и из транзакций DKV |

Строки (`row_kind`): `line` — линия; `noline` — часы заказчика без линии; `unallocated` — «Не розподілено» по статье (с подсказкой вида), по
виду без линии, «DKV: рахунок без транзакцій», «DKV різниця» (счёт ≠ его транзакциям), «DKV: картка без періоду», «Перевезення без
прибуттів»; `office` — «Офіс» (по статье или
карте DKV); `owner` — «Власник» по статье аналитики (узел «… / Owners», решение 05.11 R09); `ignore` — «Не враховано»; `dkv` — счета DKV, вместо
которых считаются их транзакции. «Чисто» строки компании: «Офіс», «Власник», «Не розподілено» — сумма (кроме буфера жилья и денег линии без
линии); «Не враховано» и `dkv` — 0.

## Откуда берёт
- **Часы** — `account.analytic.line`: проект есть, счёта (`general_account_id`) нет, работник есть, часы > 0; фирмы — периметр «Ставок»
  (`workset_rates.out_of_perimeter_company_ids`). Человек — `hr.employee.work_contact_id` (та же связь «карточка → контакт ставки», что в
  «Ставках»: `_pair_hour_rows`, «Працюють»); по имени не сопоставляем — карточка с другим контактом даёт часы «без ставки». Заказчик —
  `project_id.partner_id.commercial_partner_id`, линия — `workset.line`, у которой заказчик в `customer_ids` (первая по порядку линий).
- **Частка** — `workset.rate._plan_at(pairs, day)` на первый день каждого отрезка месяца между новыми ставками пары (смена ставки
  внутри месяца). Нет ставки — `None`, часы — в `hours_no_rate`. Ключей `worker_fund_share` / `car_rent_share` в ответе нет — 0.
- **Расходы** — `account.analytic.line` с `general_account_id` и статьёй (`account_id`) под корнями плана рекрутинга: параметр
  `workset_profit.root_plan_ids` (id через запятую); нет параметра — корни узлов линий (`workset.line.plan_ids`). Сумма — в EUR (курс даты
  строки). Месяц (`calc.service_period`): у строки счёта есть `deferred_start_date` / `deferred_end_date` (поля бухгалтерии, если есть в
  сборке), параметр `workset_profit.split_by_period` не «ні» и **у счёта нет проводок отсрочки Odoo** (`deferred_move_ids` /
  `deferred_original_move_ids`) — по дням периода (центы раскладываются без потерь); иначе — по дате строки. Проводки отсрочки Odoo уже
  разносят сумму по месяцам своими датами — делить счёт с ними значило бы считать дважды (известный сдвиг без периода: аренда двух месяцев
  одним счётом видна в месяце счёта).
- **Кто платит** — житьё: `workset.line.housing._housing_at(линия, заказчик, день)` «Ставок» (`we_buffer`, `customer` — мы; `partner` —
  партнёр; `worker_fund` — фонд, если «Ставки» добавят такое значение); авто, паливо, інструмент, перевезення — `workset.line.cost.rule`
  (правило заказчика точнее правила линии; нет правила — мы).
- **Житло, которое вычитает заказчик** (`housing_customer`, `calc.customer_housing`): на каждый день с часами у заказчика линии — правило
  `_housing_at`; «Хто платить» = заказчик и сумма есть → по единице правила: «€ за місяць» — сумма за человека в месяц (люди с часами в
  месяце у этого заказчика; один раз — в первый день, когда правило действует; так задание круга 1б читает «вычитает заказчик за месяц»,
  хотя подпись единицы в «Ставках» — «(об'єкт)»), «€ за добу за особу» — × человеко-дни с часами, «€ за годину житла» — × часы, «% з оплати» — % от
  часы × «Платять нам». Если такой вычет ещё и стоит строкой в аналитике (кредит-нота, скидка) — её размечать `ignore`, иначе второй раз.
- **DKV** — `workset.dkv.txn` (брутто EUR — так проведено в книгах) → период карты на дату транзакции: линия → «Паливо» по «Хто платить»,
  офис → строка «Офіс» карты, перевезення → между линиями по прибытиям; периода нет — «Не розподілено». Счёт с транзакциями — привязанными
  полем `move_id` или (поле пусто) по номеру счёта DKV `invoice_no` = «Референс» (`ref`) счёта: его аналитика — строка `dkv`, не второй раз;
  разница «аналитика счёта − брутто его транзакций» (частичная загрузка) — в месяц пропорционально доле месяца строкой «Не розподілено: DKV
  різниця» (`calc.dkv_bill_entries`). Счёт DKV без транзакций (разметка `dkv_bill`) — «Не розподілено: DKV». Транзакции без счёта в Odoo
  (API, счёт ещё не выставлен) — по линиям; в сверке — «Транзакції DKV без рахунку в Odoo: N, сума», а если в месяце есть и счёт DKV без
  транзакций — предупреждение о возможном двойном счёте (привязать транзакции к счёту).
- **Перевезення людей** (решение владельца 06.11 «перевозка: на линию») — транзакции карт с периодом `transport` и аналитика вида
  `transport` без линии делятся между линиями по числу прибытий месяца. Прибытие — начало периода работы человека по табелям (разрыв между
  соседними датами > 45 дней — новый период, как `STINT_GAP_DAYS` в `tools/lib/odoo_arrivals.js`); человек — склеенные карточки, как
  `buildPersons` там же (`calc.glue_people`: общий телефон, кроме записанного у двух и более разных имён; одинаковое имя без приписки фирмы
  « | TF» / « | PA»; общий рабочий контакт) — карточки одного человека в разных фирмах не дают нового прибытия; линия — по заказчику первого
  дня периода (больше часов). Прибытий нет — «Не розподілено: перевезення без прибуттів». Кто платит — правило «Хто платить» вида
  `transport` линии. Ставка же ищется по-прежнему по контакту карточки (как в «Ставках»).

## Разметка аналитики (`workset.profit.analytic.map`)
Ключи правила — узел плана, статья аналитики, счёт, контрагент; правило берёт сумму, когда совпадают **все** заполненные ключи.
Точнее: контрагент > статья > счёт > узел (ключи складываются), затем глубже узел, позже «З». Линии в правиле нет — линия по узлу статьи
(глубже — точнее) или по заказчику (правила или контрагент статьи). Без правила — «Не розподілено» по статье и счёту; подсказка вида по
имени (`calc.kind_hint`: Жилье / Житло, Жилье + Буфер, Топливо / Паливо, Инструмент / Спецодежда, Транспорт / Вождение / Лизинг) — только
в форме разметки и в имени строки «Не розподілено», считает разметка.

| Вид | Подпись | Куда идёт сумма |
|---|---|---|
| `housing` | Житло | линия: «Житло» (мы) / «З грошей лінії» (партнёр) / «З фонду» — по правилу житла линии «Ставок» |
| `housing_buffer` | Буфер житла (довідково) | линия: «Буфер житла», в «чисто» не входит (часть оплаты заказчика через «Передача ліквідності») |
| `fuel` | Паливо | линия: «Паливо» / партнёр / фонд — по «Хто платить» |
| `tool` | Інструмент і спецодяг | линия: «Інструмент» / партнёр / фонд |
| `auto` | Авто | линия: «Авто» / партнёр / фонд |
| `transport` | Перевезення людей | линия: «Перевезення»; без линии — между линиями по прибытиям |
| `dkv_bill` | Рахунок DKV | есть транзакции по счёту — строка `dkv` (не второй раз); нет — «Не розподілено: DKV» |
| `partner` | Гроші лінії (партнер) | линия: «З грошей лінії» (узлы «… / Partners») |
| `owner` | Власник | строка «Власник · <статья>» (узел «Recruting / Owners»), не линия |
| `office` | Офіс | строка «Офіс · <статья>» |
| `ignore` | Не враховувати | строка «Не враховано»: в сверке, не в «чисто» (выручка, зарплата — они уже в частке ставок) |

Вид линии без линии — «Не розподілено (… без лінії)». Пример разметки: узел линии → `ignore` (выручка и зарплата), счёт «Топливо» в
зарплате → `fuel` (счёт точнее узла), статья «Жилье | Расход | …» → `housing`, поставщик DKV → `dkv_bill`, узел Owners → `owner`;
оренда авто в аналитике (доход линии вроде SoMa) → `ignore`: аренду уже считает ставка (`car_rent` = часы × `car_rent_share`), иначе она
войдёт в «чисто» второй раз.

## Модели и виды
- `workset.profit.month` — «Лінії × місяці»: список (кнопки «Перерахувати» — редактор, «Звірити»; группировка по месяцу; рядки пишет только
  код), сводная (строки × месяцы, «Чисто»), график, карточка строки (нулевое скрыто).
- `workset.line.cost.rule` — «Хто платить»: линия, заказчик (необязательно), вид (`auto`, `fuel`, `tool`, `transport`), кто платит (`we`,
  `partner`, `worker_fund`, `customer`), с–по; одно правило на «линия × заказчик × вид» на дату; история изменений.
- `workset.dkv.card` + `workset.dkv.card.period` — «Картки DKV»: номер (уникальный), порядковый № в кабинете DKV, машина (`fleet.vehicle`);
  периоды «лінія [+ замовник] / офіс / перевезення людей» с датами (один на дату), правка на месте в карточке.
- `workset.dkv.txn` — «Транзакції DKV»: дата, карта, страна, город, группа товара, количество, нетто и брутто EUR, номер счёта DKV, счёт
  поставщика Odoo (необязательно), источник `pdf` / `api`, «Ключ рядка» (уникальный — повтор записи не множит).
- `workset.profit.analytic.map` — «Розмітка аналітики» (выше).

## Пересчёт и сверка
- `workset.profit.month.profit_recompute(date_from=None, date_to=None)` — месяцы периода (нет — 3 последних с текущим; не больше 36 за
  раз): строки месяца заново (старые удаляются), затем сверка; → `{'months', 'rows', 'verify'}`. Только редактор прибутковости или
  администратор; `sudo` — только внутри пересчёта и сверки. Кнопка «Перерахувати» — месяцы выбранных строк или 3 последних.
- Плановое «Прибутковість: щоночі» (`data/ir_cron.xml`) — 23:00 UTC (после «Ставки: щодня» 22:15 UTC), 3 последних месяца, включено.
- `_verify(month)` («Звірити»; для инструмента — публичный `profit_verify(date_from, date_to)`, только чтение, право — читать итог) —
  сумма денег аналитики в строках = аналитика плана за месяц (та же выборка, части периодов и курс) до цента; **отдельный подсчёт**
  аналитики плана, датированной месяцем, — `_read_group` по фирмам (не через `_analytic_items`), в валюте фирмы — равен тем же строкам в
  расчёте (ловит строку, которую расчёт потерял); деньги DKV в строках = минус брутто транзакций месяца; в каждой строке столбцы дают её
  сумму; расхождение — текстом с числами. Справочно в тексте: сколько периоды услуги перенесли между месяцами; транзакции DKV без счёта в
  Odoo (N, сумма) и предупреждение о возможном двойном счёте, если в месяце есть и счёт DKV без транзакций.

## Права
Привилегия «Прибутковість» (раздел кадров формы пользователя): «Перегляд» — читает всё; «Редактор» (включает «Перегляд») — правит
«Хто платить», карты и транзакции DKV, разметку, пересчитывает; удаляет — системный администратор (периоды карты — и редактор, правка на
месте). Итог `workset.profit.month` пишет только код. «Перегляд» читает линии «Ставок»; аналитику, счета и машины — по своим правам
бухгалтерии и автопарка (строки итога несут готовое имя).

## Системные параметры (пишет инструмент штаба)
| Параметр | Смысл |
|---|---|
| `workset_profit.root_plan_ids` | id корневых планов аналитики рекрутинга через запятую; нет — корни узлов линий |
| `workset_profit.split_by_period` | делить строку счёта по периоду услуги: «так» / «ні» (нет — так; счёт с проводками отсрочки Odoo не делится никогда) |
| `workset_rates.out_of_perimeter_company_ids` | (модуля «Ставки») фирмы вне периметра: их табели в часы не идут |

## Установка
1. Сначала `workset_rates` (19.0.3 — с фондом працівників и арендой авто в `_plan_at`), затем этот модуль: папка — в репозиторий Odoo.sh
   (ветка копии → сборка и тесты → `main`); помощник штаба `node tools/odoo_sh_push.js --module workset_profit` (план; выкладывает coordinator).
   Зависимости: `workset_rates`, `fleet` (приложение «Автопарк»).
2. Установка и обслуживание — инструмент штаба `tools/odoo_workset_profit.js` (`--target copy|prod` обязателен; без `--apply` — план,
   код 3; прод — только с `--confirm-prod <база>` и вне пн–пт 9–17 по Киеву):
   `--install` — обновить список модулей, установить / обновить `workset_profit`, дождаться installed;
   `--recalc --from ГГГГ-ММ --to ГГГГ-ММ` — пересчитать месяцы (`profit_recompute`) и показать сверку каждого;
   `--verify [--from ГГГГ-ММ --to ГГГГ-ММ]` — только чтение: модуль, виды, меню, группы, плановое, сверка месяцев (`profit_verify`).
   Параметр `workset_profit.root_plan_ids` и посев данных (разметка, «Хто платить», карты DKV с периодами, транзакции из PDF счетов DKV)
   готовит штаб отдельно — в инструменте их нет.
3. «Перерахувати» (или `--recalc`) → «Звірити» (или `--verify`): строки «Не розподілено» — что ещё разметить.

## Тесты
`tests/test_workset_profit.py` — `TransactionCase`, теги `post_install`, `-at_install` (Odoo.sh — на dev-сборке): смена ставки внутри
месяца, часы без ставки, оренда авто и фонд, житло «мы» / «партнёр», буфер не в «чисто», DKV по карте → линия / офис / перевозка по
прибытиям (2 линии, 3 прибытия), счёт DKV без транзакций, без прибытий, узел Owners → «Власник», сверка сходится и ловит расхождение,
пересчёт не множит строки, плановое — 3 месяца, правила и запреты, права. Без Odoo:
`node tools/odoo_sh_push.js --module workset_profit --print-check-params > p.json`, затем
`uv run --python 3.13 python -I tools/odoo_addon_check.py tools/odoo_addons/workset_profit < p.json`; и
`node --test tools/tests/odoo_workset_profit_module.test.js` (чистые функции `models/calc.py`, перевод, виды, права).
