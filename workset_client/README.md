# workset_client — «Умови клієнтів» (М3, К1)

Модуль Odoo 19.0 для репозитория Odoo.sh `ERP-Ukraine/workset`. Карточка заказчика, где его условия «прописаны и понятны, чтобы ничего не
забывалось» (слово владельца 07.11): что платят нам и на руки, чья доля, кто платит жильё, перевозку, топливо, инструмент и авто, агент,
договор и оплата, что из этого выходит за месяц, квартал или год и что недавно менялось. Принятый вид — макет D (`runtime/shared/2026-11-06-m3-pributkovist-liniy/maketi/D-umovy-kliienta.png` в штабе).
Здесь только устройство; сумм, имён людей и заказчиков в коде нет.

**Карточка — представление, а не второе место ввода.** Почти всё уже лежит в «Ставках» (`workset_rates`), «Прибутковості»
(`workset_profit`) и «Агентах» (`workset_agents`); карточка собирает это по заказчику, показывает итог после перекрытия «заказчик точнее
линии» и откуда он взят, а клик ведёт в источник — править там, где правят сейчас. Своё — только то, чего нигде нет (ниже, «Свои поля»).

## Экран «Умови клієнта» (client action `workset_client.card`, путь `/odoo/workset-client`)
Один вызов сервера `res.partner.workset_client_card(partner_id, period, month)` (`models/client_screen.py`); выбор правил и итог периода —
чистые функции `models/calc.py` поверх функций соседей (тех же, не копий). Заказчик — коммерческий контрагент (`commercial_partner_id`):
контакт фирмы открывает карточку фирмы. Линия заказчика — первая линия, где он в `workset.line.customer_ids` (порядок «Ставок»); нет —
линия большинства его действующих ставок.

| Блок | Число | Откуда |
|---|---|---|
| Шапка | имя, страна, НДС (`vat`), линия, проекты; «Перевірено <дата>» или жёлтое «не перевірено» | `res.partner`; `workset.line.customer_ids`; `project.project.partner_id`; свои поля `workset_client_checked_*` |
| Гроші за годину | «Платять нам», «На руки» — диапазон; «Частка WorkSET» — среднее; «діє N ставок» | `workset.rate` заказчика со статусом «Діє» сегодня: `price`, `wage`, `our_share` (`calc.money_range`, `calc.share_avg`) |
| | «Мінімум частки» (нет — жёлтое «не задано») | `workset.rate.rule.min_share` общей ставки пары «лінія × замовник» на сегодня — `rcalc.rule_pick` (тариф заказчика точнее правила линии) |
| | «Відсоток за виведення коштів» (нет — серое «—») | своё поле `workset_client_withdraw_pct`; справочно, в расчёт прибыли не входит |
| Хто платить | Житло | правило жилья «Ставок» `workset.line.housing` — `rcalc.housing_pick` (заказчик точнее линии, действует сегодня): «Хто платить» (пусто — «Як рахуємо»), сумма и единица, «З», «Звідки саме» |
| | Перевезення людей, Паливо, Інструмент, Авто | правила «Хто платить» `workset.line.cost.rule` — `pcalc.cost_rule_pick` (заказчик точнее линии); нет — «Ми (правила немає)» серым |
| | карты DKV у «Паливо» | периоды карт `workset.dkv.card.period` на сегодня (`pcalc.card_period`): «Лінія» с этим заказчиком или с его линией без заказчика |
| | Оренда авто | `workset.rate.rule.car_rent` общей ставки пары; 0 — «не діє» |
| | Фонд працівників | договорённость вида «Фонд працівників» модуля «Агенти» (`rcalc.deal_fits`) или доля фонда в ставках (`worker_fund_share`); нет — «не діє» |
| Агент і хто знайшов | агент по заказчику | `workset.agent.deal.client` «€ за годину» и «Фікс-аванс», действующие (`rcalc.deal_fits`); модели нет — «модуль агентів не встановлено» |
| | агент линии (справочно) | `workset.line.agent_id` |
| | «Хто знайшов людей»: «ми N · лінія M», не указано — жёлтое «не вказано у K з N» | `found_by` действующих ставок (`rcalc.found_split`) |
| Договір і оплата | № и дата договора, скан, срок оплаты, кто согласует табель, контакт и адрес объекта, особые договорённости; пусто — жёлтое «не внесено» / «не задано» | свои поля + стандартный `property_payment_term_id` (им пользуются счета) |
| Що з цього виходить | частка, оренда авто, житло (с тем, что вычел заказчик), авто, паливо, інструмент, перевезення, чисто; с 19.0.3 «Прибутковості» — ZUS і загальні, Залишається; € год — на часы со ставкой периода | строки линии `workset.profit.month` за месяцы периода (`calc.period_rows` поверх `pcalc.totals` / `remain_totals`); месяц без итога «ZUS і загальні» — «не перераховано», а не 0 |
| Останні зміни | 10 последних: «дата · что: было → стало · кто» | трекинг своих полей заказчика, его ставок (всех), правил жилья и «Хто платить» линии × заказчика; создание этих правил и периодов карт DKV |

Период «Місяць | Квартал | Рік» (стрелки — соседний период): по умолчанию — последний закрытый месяц; квартал и год — календарные;
только с января 2026 (`pcalc.MIN_MONTH`, как экраны «Прибутковості») и не дальше текущего месяца (`calc.period_info`).

Переходы: каждое число и строка открывают свой источник — сервер отдаёт описание `open` (модель, домен, заголовок, без «Створити»;
`res_id` — форма одной записи), только если пользователь сам читает эту модель; нет прав — без клика. «Картка лінії ›» — экран
`workset_profit.line_card` линии на последний месяц периода — только группе «Прибутковість: Перегляд». «Заповнити» и «Позначити
перевіреним» — только редактору. Клавиатура: элемент с кликом — `role="button"`, `tabindex`, Enter / пробел.

## Свои поля (`res.partner`, префикс `workset_client_`, история изменений, не копируются)
`contract_no` (№ договора), `contract_date`, `contract_scan_ids` (скан, `ir.attachment`), `sign_id` (кто согласует табель — контакт
заказчика), `site_contact_id` (контакт на объекте), `site_address`, `withdraw_pct` (%, справочно), `terms_note` (особые договорённости),
`checked_date` и `checked_by_id` (кто проверил). Срок оплаты — стандартное `property_payment_term_id`, своего поля нет.
Правка — окно «Заповнити» (`workset.client.terms`: пишет в контакт только изменённое, сканы переходят к контакту) и «Позначити
перевіреним» (сегодня по Киеву и текущий пользователь).

## Список «Умови клієнтів» (меню «Умови клієнтів → Клієнти», путь `/odoo/workset-clients`)
Заказчики из «Замовників» линий или с действующими ставками (`workset_client_is_customer`). Колонки: заказчик, линия, ставок действует,
доля ср., жильё — кто платит, договор (є / не внесено), срок оплаты, проверено; пустое — жёлтым словом. Фильтры «Без договору», «Без
терміну оплати», «Не перевірено». Строка открывает экран (js_class `workset_client_list`), не форму контакта. Смарт-кнопка «Умови» на
форме контакта заказчика.

## Права
| Группа | Что |
|---|---|
| `workset_client.group_viewer` «Перегляд» | меню, список, экран (метод проверяет группу сам — `_workset_client_check_view`); числа читаются sudo |
| `workset_client.group_editor` «Редактор» (включает «Перегляд») и `base.group_system` | свои поля (`create` / `write` контакта проверяют группу), «Заповнити», «Позначити перевіреним» |

На время сборки «Перегляд» есть у каждого внутреннего пользователя (слово владельца 07.11: «бачать картку: всі, з часткою, пока делаем
функционал, а когда будет готово я решу по доступу»): одна запись в `security/workset_client_security.xml` — `base.group_user` включает
`group_viewer`. **Что дальше:** доступ решает владелец по готовому экрану; снять — `(4, ref('group_viewer'))` → `(3, ref('group_viewer'))`
в этой записи и обновление модуля, затем состав `group_viewer` — по его слову. Правила-источники правятся там, где их правят сейчас
(группы «Ставок» и «Прибутковості»).

## Установка
После `workset_rates` и `workset_profit` (зависимости в манифесте; `mail` — история изменений). «Агенты» (`workset_agents`) — мягко:
есть модель `workset.agent.deal.client` — читается, нет — блок пишет «модуль агентів не встановлено». Данных модуль не пишет.

## Тесты
- Без Odoo: `node --test tools/tests/odoo_workset_client_module.test.js` — проверка публичности и устройства (`tools/odoo_addon_check.py`
  с параметрами `node tools/odoo_sh_push.js --module workset_client --print-check-params`), перевод, чистые функции `models/calc.py`
  (стенд `tools/odoo_addon_calc.py` с `alias`: calc «Ставок» и «Прибутковості» подставляются под их именами в Odoo), виды, права.
- Odoo: `tests/test_workset_client.py` (синтетика 2030 года) — на dev-сборке Odoo.sh.
