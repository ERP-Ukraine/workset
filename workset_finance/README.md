# workset_finance — «Фінанси» (круг 1: слой данных, круг 2: экран «Власник»)

Модуль Odoo 19.0 для репозитория Odoo.sh `ERP-Ukraine/workset`. Здесь только устройство (модели, расчёт, права, плановое, экран); параметры и состав
групп пишет инструмент штаба через API (`tools/odoo_finance_screens.js --seed`). Имён людей, заказчиков, сумм и номеров записей в коде нет.
Круг 1 — хранимый «месяц драбини», поправки, звірка, простые виды; круг 2 (19.0.1.1.0) — экран «Власник» (ниже); экраны «Замовники»,
«Фірми: закриття місяця», «Зарплата й конверти» — круги 3–5. Архитектура: `runtime/shared/2026-11-06-ekrany-po-rolyam/01-arhitektura.md`.

Ставить после `workset_rates` (периметр фирм, линии). Месяцы — только с января 2026 (`calc.MIN_MONTH`).

## Что считает
Одна запись `workset.finance.month` на месяц (`UNIQUE(month)`), поле `*_src` у каждой ступени: `fact` [факт] — книги Odoo, `calc` [розрах.] —
расчёт штаба, `adjust` [поправка] — есть активная поправка.

| Поле | Что | Откуда |
|---|---|---|
| `s1_docs` | 1 Рекрутинг по документам | `account.analytic.line` корня плана рекрутинга (`account_id.root_plan_id`), P&L-счета (`calc.PL_TYPES`), проведённые, фирмы периметра, за месяц |
| `s1a_owners_in_pl` | 1а Власники в P&L | минус те же строки с `account_id.plan_id child_of` узла Owners (возврат в прибыль; эти деньги идут в 5) |
| `s1g_no_analytic` | 1г Доход без аналитики | **только поправки** `workset.finance.adjust` ступени `s1g`; рядом `g_cand_*` — кандидаты (оплаченные счета клиентов без аналитики, месяц по дате последней оплаты) |
| `s2_ukraine` | 2 Україна | аналитика фирмы Украина на счёте ликвидности по плану Украина (параметры) |
| `base` | До часток | 1 + 1а + 1г + 2 |
| `s3_shares` | 3 Частки партнерів | сумма активных поправок ступени `s3` (по линиям, если заданы); положительное число |
| `s4_net` | 4 Чистий прибуток | `base − s3_shares` |
| `s4c_cash` | 4' За грошима | `base − cash_out`; `cash_out` = **проводки** «II етап» за месяц (круг 1е): строка аналитики статьи, а если в проводке её нет — строки счёта «II этапа» этой проводки **без аналитики** (круг 2, ревю 1е — как документ v2: пара «+X без аналитики / −X со статьёй» иначе давала 0, строка конверта AN считалась бы второй раз; строки счёта с другой статьёй — не в 4', примечание звірки «рядків рахунку з іншою статтею: N на X», `calc.stage2_other` = `stage2Other` лестницы) (знак и сумма как у строки статьи; проводка с обеими — один раз, строкой статьи; деталь такой строки — отдельной строкой `cash` / `cash_other` модели `account.move.line` с пометкой), попавшие по тексту на распознанную линию (`stage2_partner_lines` — МАССИВ пар `[[фраза, id линии], …]`; текст = `name` строки + имя партнёра строки или проводки через пробел; подстрока, без регистра; совпадение — ПЕРВАЯ пара по порядку массива, не по длине фразы: порядок — правило штаба, «Anna Kowalski» идёт к первой паре, хотя «Kowal» тоже в тексте; транзит проверяется раньше всех), × 9 (× 10 брутто — в примечании строки) + минус отрицательные строки конверта AN как есть. Строки статьи положительные (доля 10 %), брутто = Σ как есть. Партнёра у этих строк почти нет — получатель в тексте `name`. Фразы из `stage2_transit_phrases` (транзит) — строка «транзит», не в 4'; без совпадения — «не розпізнано» (сумма × 9), не в 4'; обе — отдельный вид строк `cash_other` с пометкой «в 4' не входить». Линии нет в базе — строка без линии и пометка в звірці. Текст строки счёта — `name` + имя партнёра строки или документа |
| `s5_owners`, `s5_owners_share` | 5 Власники (из них «частка») | минус аналитика узлов Owners; «частка» — статьи из параметра `owners_share_analytic_ids` |
| `s6_stage2` | 6 II етап | аналитика статьи «II етап» + баланс его счёта по проведённым строкам |
| `s7_unpaid_customers`, `s7_unpaid_energy` | 7 Неоплачено | неоплаченные клиентские счета месяца с долей рекрутинга: контрагенты Energy (`energy_partner_ids`) — **проверяются раньше межфирменных** (фирма Energy есть в Odoo, её партнёр входит и в «свои» фирмы; иначе Energy всегда 0); затем межфирменные (контрагент — фирма периметра или архивная) и партнёры фирм вне периметра (не из Energy) не показываем; остальные — замовники; только `out_invoice` / `out_refund`; **на момент пересчёта** |
| `mediation_*` | Посередництво | аналитика плана посредничества: доход / расход / остаток |
| `revenue`, `payroll`, `contrib_zus` | справочно | доходные строки вынборки 1; расходы в журналах зарплаты; расходы на контрагентах ZUS |
| `q_*`, `q_pct` | Якість даних | как «месяц правдив» закрытия месяца (`node tools/odoo_month_close.js --check`) и сторожа, круг 1е: «міжфірмові» — `MC.truthTurnover` (вся строка документа с партнёром — своей фирмой, кроме транзита); «без місця» — `PG.identity` (ниже); «банк без документа» — `PG.bankNoDoc`: несверенные строки выписок месяца **без окна 14 дней**, сумма в **EUR** — `balance` строки проводки на счёте журнала (не `amount` выписки: журналы в злотых), дубли выписок отсеяны, только 4 вида: ZUS и налоги, без партнёра, фирма без счетов поставщика, физлицо без счетов; не «без документа» — свои фирмы, посредники (`mediator_partner_ids`), работники, зарплатные листы, партнёры со счетами поставщика в этой фирме; оборот с внешними — без своих фирм, фирм вне периметра и посредников; доля = Σ\|корзин\| / оборот, как `MC.truthShare`. Детали: `quality/ic`, `quality/unplaced` (клик — ровно строки с вкладом), `quality/nodoc:<вид>` по каждому непустому виду (клик — строки выписки). «Свои» партнёры — как `partnerSets` закрытия месяца (`tools/lib/odoo_pnl_guard.js`): партнёры фирм периметра и архивных — «міжфірмові», партнёры фирм вне периметра — отдельная корзина (не «міжфірмові», не «без місця», не оборот); оборот с внешними — все `out_*` (`out_invoice`, `out_refund`, `out_receipt`), как `/^out_/` в `MC.truthTurnover`; документы «транзита Energy» (`quality_transit_move_ids`, по id `account.move`, как `transitIds` в `MC.truthTurnover`) не оборот и не «міжфірмові» (в контроле ступени 1 остаются; в «без місця» — как у `PG.identity`, только нераспределённый остаток) |
| `state` | открыт / закрыт | закрыт, когда даты блокировки всех фирм периметра (с учётом родительской фирмы, `parent_id`) не раньше последнего дня месяца |

Детали кликов — `workset.finance.item` (вид: `step`, `owner`, `owner_share`, `ukraine`, `stage2`, `cash`, `unpaid`, `candidate`, `transfer`, `quality`,
`adjust`; модель и домен списка в полях, кнопка «Записи» открывает их правами пользователя). Переводы на личные счета (`transfer`) — строки банковских
выписок фирм периметра по фразе банка или получателям, сумма в EUR (`balance` строки на счёте журнала, круг 1е), статус `is_reconciled`: «розібрано» / «без документа»
(статуса ведомости в Odoo нет); клик — сами строки выписки.
Поправки — `workset.finance.adjust` (подстава обязательна, дата источника, автор — создатель записи, chatter, архив вместо удаления; правит группа «Поправки»).
Звірка — `workset.finance.check` (как `workset.profit.check`).

Периметр фирм — все активные компании минус `workset_rates.out_of_perimeter_company_ids` (`workset.rate._skip_companies()`); архивные фирмы в выборку
не входят. Расчёт идёт под `sudo` (видит все фирмы), поэтому **каждое** чтение строк аналитики, проводок, документов, сверок оплат и выписок ограничено
фирмами периметра явно (`('company_id', 'in', cos)`; ступень 2 — одна фирма Украина): строки AN, «II етап», власників и посредничества фирм вне периметра в ступени не попадают. Контроль ступени 1 — вторым способом: проводки × `analytic_distribution` (доля рекрутинга по каждому ключу распределения, округление до цента);
расхождение больше одной копейки — звірка «не зійшлася». Odoo 19 сам держит распределение проводки в ладу со строками аналитики: `account.analytic.line.unlink()` и `write()`
зовут `move_line_id._update_analytic_distribution()` (`addons/account/models/account_analytic_line.py`) — удаление строки через ORM стирает и распределение, оба способа
сходятся, а сумма уходит в «без місця». Контроль ловит расхождение мимо ORM: SQL, миграция, код с контекстом `skip_analytic_sync`.

«Без місця» модуля (`q_unplaced`) с круга 1е — правило сторожа P&L и закрытия месяца (`PG.identity` в `tools/lib/odoo_pnl_guard.js`, `unplaced = ext + other + broken`;
порт — `calc.identity_unplaced`, паритет до бита — тест node): каждая P&L-строка раскладывается по распределению на rec / med / other / broken при любом партнёре (доли
статей других планов и удалённых статей — «без місця» и у межфирменных, и у транзита), нераспределённый остаток — по документу и партнёру: транзит / ic / вне периметра /
посредники и «только списание» (`excluded_partner_ids`) — не «без місця», внешние — «без місця». Сумма — **со знаком** (дохід и расход без места гасят друг друга), доля берёт
модуль от суммы — так считает `MC.truthShare` закрытия месяца; правило не меняли, чтобы доля модуля = доле `--check` (сумма модулей по строкам — `gross` в
`calc.identity_unplaced`, как `unplacedGross` сторожа, — для разбора). Клик `quality/unplaced` — ровно строки с вкладом (раньше — «строки без распределения», клик ≠ сумма).
До круга 1е модуль считал свою корзину (только документы внешних партнёров, «свои» и транзит — целиком вне), её сверка шла с JS-лестницей — тем же портом.

## Параметры (`ir.config_parameter`, префикс `workset_finance.`)
Обязательные (нет — понятная ошибка «параметр не посіяно»): `recruting_plan_id`, `owners_plan_id`, `ukraine_company_id`, `ukraine_plan_id`,
`liquidity_account_id`, `stage2_analytic_id`, `stage2_account_id`. Необязательные: `owners_share_analytic_ids`, `stage2_partner_lines` (JSON-массив пар `[фраза, id линии]`, порядок = приоритет; разбор в модуле и в JS-лестнице один: не JSON (и `NaN` / `Infinity`) или не массив — пусто, пара — массив ровно из двух, фраза — непустая строка, линия — JSON-число без дробной части от 1 до 2147483647, не `true`, не строка `"5"`; прочие пары пропускаются; общие случаи — `tools/tests/fixtures/finance_phrase_pairs_cases.json`; правила фраз — ниже),
`stage2_transit_phrases` (JSON-массив фраз транзита «II етап»), `an_envelope_analytic_id`, `mediation_plan_id`, `energy_partner_ids`, `excluded_partner_ids` (посредники и
«только списание», `X.noAnalyticsIds`: «без місця» и кандидаты 1г), `mediator_partner_ids` (только посредники — параметр, список `X.MGMT_EXCLUDED_IDS`: оборот с внешними
и вид «посредники» банка — как у закрытия месяца; не посеян — их платежи пойдут в «без документа», а звірка месяца скажет «параметр не посіяно»),
`quality_transit_move_ids` (документы транзита Energy), `transfer_phrases` (JSON-массив фраз банка «на личный счёт»; обычная строка читается как одна фраза),
`transfer_partner_ids`, `zus_partner_ids`, `payroll_journal_ids`. Файл посева — `tools/lib/workset_finance_seed.json` (id прода лежат там, в модуль не попадают).
Фразы `stage2_partner_lines` и `stage2_transit_phrases` — имена людей и IBAN, то есть персональные данные: в git их нет, `--seed` читает их из отдельного файла вне git
(`data/finance/workset_finance_seed_private.json`, ключ `--private <путь>`; файла по умолчанию нет — параметры не пишутся, предупреждение; явно названного файла нет — ошибка, код 2), в вывод значения не печатаются. В публичном файле посева эти ключи должны быть пустыми — иначе отказ. Формат приватного файла: `{"params": {"stage2_partner_lines": [["фраза", 1], …], "stage2_transit_phrases": ["…"]}}`; объект вместо массива пар — понятная ошибка посева.

Правила фраз (`stage2_partner_lines`, `stage2_transit_phrases`, `transfer_phrases`) — одни в `calc.py` и в JS-лестнице (круг 1д): края фразы режет один набор пробельных
`calc.PHRASE_WS` = `PHRASE_WS` лестницы — объединение `str.strip()` Python и `String.prototype.trim()` JS (они режут разное: strip — ещё `\x1c`–`\x1f` и `\x85`, trim — ещё
BOM U+FEFF; пробел нулевой ширины U+200B не режет никто). Фраза — только строка; фраза-число (без пробельных — цифры со знаком и, может, дробью через «.» или «,»:
`"123"`, `"12,5"`, `"1 234,56"`; цифр не больше `calc.PHRASE_NUM_MAX_DIGITS` = 7) и JSON-число — не фраза: подстрока-сумма или год нашлась бы в чужих строках. Хвост счёта или
карты от 8 цифр — фраза. Разбор такие фразы пропускает (ошибки в разборе не бывает), звірка месяца называет параметр и сколько пропущено (`calc.param_notes`), посев
отклоняет файл с номером пары или фразы, без самой фразы.

## Группы и методы
Привилегия «Фінанси»: «Замовники», «Фірми: закриття місяця», «Зарплата й конверти» (круги 3–5), «Власник» (включает три выше), «Поправки» (включает «Власник»).
Состав групп — данные (посев). Методы (все проверяют группу сами, администратор поза групою экраны не видит, суперпользователь — плановое и тесты):
- `finance_recompute(months=None)` — группа «Поправки» или администратор: пересчёт (нет списка — 3 последних месяца и текущий; больше 36 месяцев за раз — понятная ошибка) и звірка каждого;
- `finance_verify(months=None)` — группа «Власник»: `{'months': [...], 'companies': [id периметра], 'intercompany_partner_ids': [партнёры фирм периметра и архивных], 'out_of_perimeter_partner_ids': [партнёры фирм вне периметра]}`; месяцы — числа, посчитанные наново (ничего не пишет), `stale` — записанное не совпадает; периметр JS-лестница берёт отсюда, а «своих» партнёров считает сама (`partnerSets` по `res.company`) и сверяет с этими списками;
- `finance_owner(month=None)` — группа «Власник»: экран «Власник» одним вызовом (ниже, `models/workset_finance_screens.py`).
Плановое «Фінанси: щоночі» — 23:30 UTC, после «Ставок» и «Прибутковості». Пересчёт под `pg_advisory_xact_lock` месяца.

## Как пересчитать и сверить
```
node tools/odoo_finance_screens.js --target copy --install --apply
node tools/odoo_finance_screens.js --target copy --seed --apply        # параметры и группы из tools/lib/workset_finance_seed.json
node tools/odoo_finance_screens.js --target copy --recalc --from 2026-01 --to 2026-11 --apply
node tools/odoo_finance_screens.js --target copy --verify --from 2026-01 --to 2026-11   # модуль против независимой JS-лестницы, до цента
node tools/odoo_finance_screens.js --target copy --rollback [--file <снимок>] [--apply] # откат по снимку посева
node tools/odoo_finance_screens.js --target copy --adjusts --file data/finance/workset_finance_adjusts_2026.json [--apply]   # поправки ступени 3 из файла
node tools/odoo_finance_screens.js --target copy --adjusts-rollback <снимок --adjusts> [--apply]                        # архивировать созданное этим снимком
```
`--adjusts` (круг 2б) — поправки ступени 3 «Частки партнерів» (`workset.finance.adjust`: месяц, ступень, линия, сумма, основание, дата источника) из файла вне git
(в нём только коды линий, без имён людей): линия — по `workset.line.code` на цели (нет кода или их два — отказ до записи); ключ — месяц + ступень + линия +
основание: та же сумма — «на месте», другая — «розбіжність» (ничего не пишется, код 1); другие активные поправки тех же месяцев — ⚠ и итог ступени 3 в плане;
1г режим не грузит (с 07.11 эти доходы уже в ступени 1 — был бы двойной счёт). Без `--apply` — план (код 3); снимок «было» и созданное —
`data/bak/odoo-workset-finance-adjusts-<цель>-<метка>.json`; после записи — подсказка `--recalc` затронутых месяцев (до пересчёта лестница поправок не видит).
`--adjusts-rollback <снимок>` архивирует созданные им поправки (архив вместо удаления, как в «Поправках»); прод — с `--confirm-prod`, как остальные записи.
`--verify` сверяет: ступени с JS-лестницей до цента; периметр фирм модуля (`companies`) со списком P&L-периметра штаба `tools/lib/odoo_perimeter.js` (`PNL_COMPANY_IDS`) —
отдельная строка таблицы; «своих» партнёров модуля (`intercompany_partner_ids`, `out_of_perimeter_partner_ids`) с независимым `partnerSets` штаба (`res.company` с архивными
ключом, фирмы вне периметра — `odoo_perimeter.js`; лестница считает по нему, а не по ответу модуля); три корзины, оборот и долю «якості даних» (`q_ic`, `q_unplaced`, `q_nodoc`,
`q_ext` — до цента, `q_pct` — до 0,1 п. п.) — с итогом закрытия месяца: `collectCheck` из `tools/odoo_month_close.js` (тот же расчёт, что печатает `--check`: `PG.identity`,
`PG.bankNoDoc`, `MC.truthTurnover`, `MC.truthShare`) по фирмам учётки ключа — свой код штаба, а не порт лестницы (до круга 1е «без документа» и «без місця» лестница считала
своим портом, сверка сходилась по кругу); отдельные строки; права — каждую строку `security/ir.model.access.csv` по внешнему id `workset_finance.access_*`.
Любое расхождение — код 1. Замечания ⚠ (код не меняют): «имя партнёра не прочитано: N» — у строк «II етап» есть партнёр, а ключ его не прочитал (нет прав, удалён):
в тексте строки у лестницы имени нет, модуль под `sudo` его видит — если 4' разошлось, причина может быть здесь; «проводка II без <статьи II этапа>, не транзит: N» (в тексте
инструмента — id статьи) — в 4' взята строка счёта «II этапа» (строки статьи в проводке нет). `--rollback`: снять добавленных посевом пользователей из групп → `button_immediate_uninstall` модуля → вернуть/удалить посеянные
параметры `workset_finance.*` (изменённые после посева не трогаются); снимок — последний `data/bak/odoo-workset-finance-seed-<цель>-*.json` или `--file`, снимок другой базы
— отказ; без `--apply` — план (в нём «поправок N, звірок M» и все снимки этой цели и базы, применяется последний); прод — только с `--confirm-prod`. Данные бухгалтерии Odoo модуль не меняет. Поправки людей (`workset.finance.adjust`, с основанием) исчезают вместе с модулем: при N > 0 `--apply` только с `--drop-adjusts` (без него отказ, код 2); перед удалением поправки (в том числе архивные) и звірки выгружаются в `data/bak/odoo-workset-finance-adjust-<цель>-<метка>.json`, не записалась выгрузка — модуль не трогается. Корзины качества `--verify` сверяет с закрытием месяца — его списки посредников и «только списание» (`X.MGMT_EXCLUDED_IDS`, `X.noAnalyticsIds`) и транзита (`X.TRANSIT_MOVES`), а не параметры модуля: расхождение списков и есть находка.
Прод — только с `--confirm-prod <база>`, вне 9–17 по Киеву, по слову владельца. Тесты: `tools/tests/odoo_workset_finance_module.test.js` (без Odoo) и
`tests/test_workset_finance.py` (Odoo.sh, `--test-tags workset_finance`).

## Экран «Власник» (круг 2: макет A + таблица «Драбина» макета B)
Меню «Фінанси → Власник» (первый пункт, открывается при входе в «Фінанси»; дальше «Місяці» — «Місяці драбини» и «Рядки», «Поправки», «Звірка»).

`AccessError`), месяц — только с января 2026 (раньше — `ValidationError`); без месяца — последний закрытый, а закрытых нет — последний завершённый
календарный (`calc.default_month`). Ничего не пересчитывает и не пишет: числа — сохранённый месяц драбини, клики — «Рядки» того же пересчёта.

Круг 2б (два ревю круга 2): колонки таблицы, ряд графика, «Разом» и «з початку року» плиток — один набор месяцев: январь … **выбранный**
